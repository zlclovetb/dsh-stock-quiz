## 3.2 `src/market-review.js` — 行情采集 + 复盘分析 + 路由（宿主侧核心）

| 项 | 内容 |
| --- | --- |
| 职责 | 聚合第三方公开行情、计算复盘分析、注册 HTTP 路由 |
| 导出 | `parseTencentQuotes`、`buildTradeData`、`analyzeMarketReview`、`buildMarketReview`、`registerMarketReviewRoute` |
| 依赖 | 仅 Node/Web 标准能力（`fetch`、`AbortSignal`、`URL`、`Response`、`TextDecoder`） |
| 行数 | 约 500 行 |

内部结构分为四层：

### （1）常量与通用工具
- `EASTMONEY_TOKEN = '7eea3edcaed734bea9cbfc24409ed989'`、`CACHE_TTL_MS = 2 * 60 * 1000`、`cache = new Map()`。
- `round` / `sleep` / `compactDate`（去横杠取 8 位）/ `displayDate`（加回横杠）。
- `request(url, {encoding, timeout, retries})`：带超时、重试、退避、`AbortSignal.timeout` 的通用抓取。
- `requestJson(url, options)`：在 `request` 基础上 `JSON.parse`，并校验 `rc === 0`。

### （2）数据源适配器（每个源一个函数）
| 函数 | 数据源 | 产出 |
| --- | --- | --- |
| `parseTencentQuotes(source)` | 腾讯行情文本协议 `v_xxx="…~…"` | 指数/个股行情行 |
| `fetchIndices()` | 腾讯财经（gbk 编码） | 四大指数（sh000001/sz399001/sh000300/sz399006）+ 两市成交额 |
| `poolUrl` / `fetchPool(endpoint, date, sort)` | 东方财富涨跌停池 | 涨停/炸板/跌停/昨日涨停池 |
| `summarizeSortedBreadth` / `fetchEastmoneyBreadth` | 东方财富 clist（按涨幅排序分页 + 二分） | 全市场涨跌分布（九档） |
| `fetchSinaBreadth` | 新浪财经分页接口（备用源） | 同上 |
| `fetchBreadth()` | 编排层 | 东财优先，失败降级新浪，双失败才抛错 |
| `fetchIndustries()` | 东方财富行业排名 | 行业涨跌 + 领涨股 |
| `subtractDays` / `fetchDailySeries` / `fetchHistoricalIndices` | 东方财富日线 kline | 指定交易日指数行情 |
| `fetchMarketHistory(date)` | 东方财富日线 | 当日/前一日两市成交额对比 |
| `fetchIndexTrend(date)` | 东方财富分时 trends2 | 上证指数当日分时点 |

### （3）分析层
- `partition(name, source, fn)`：把任何抓取包成 `{name, status:'ok'|'unavailable', source, fetchedAt, data|error}`，实现「分区独立、失败降级」。
- `groupMainlines(rows)`：按板块聚合涨停股，产出 `{name, count, maxBoard, leaders}`，取前 6。
- `buildTradeData(input, extra)`（导出）：产出交易数据看板结构（指数、分时、成交额、涨跌分布、涨跌停统计、涨停梯队、热门题材、行业、昨日涨停表现）。
- `scoreMoneyEffect({...})`：加权计算赚钱效应评分（广度 25 / 涨停 20 / 跌停 15 / 晋级 20 / 封板质量 20）与标签。
- `assessMainlines(mainlines)`：主线质量评分、`grade A/B/C`、阶段判定。
- `expectationMatrix(marketPhase, moneyScore, indexChange)`：预期×现实四象限与对应动作。
- `KNOWLEDGE_BASIS`：报告引用的 15 条知识点依据（`c01、c03、c07、c14、c17、c19、w08、w09、w10、w16、w17、w24、w27、w28、w29`）。
- `analyzeMarketReview(input)`（导出）：核心分析函数，产出 `{ snapshot, report }`。

### （4）编排与路由
- `buildMarketReview(options)`（导出）：完整采集 + 分析 + 缓存 + 汇总。
- `registerMarketReviewRoute(connection)`（导出）：`connection.fetch.register({ path: '/api/stock-quiz.recap', methods: ['GET'], ... })`。

## 3.3 `src/research.js` — 纯逻辑层

| 项 | 内容 |
| --- | --- |
| 职责 | 研究数据的归一化、统计、幂等合并（无 React、无 DOM） |
| 依赖 | 无 |
| 行数 | 约 300 行 |

### 枚举常量（供 UI 下拉与校验复用）
`REVIEW_PHASES`、`MARKET_REGIMES`、`CYCLE_DIRECTIONS`、`CYCLE_POSITIONS`、`EXPECTATION_LEVELS`、`REALITY_LEVELS`、`MAINLINE_STAGES`、`REVIEW_ERROR_TYPES`、`TRADE_SNAPSHOT_LIMIT = 90`。

### 归一化
- `normalizeResearchData(value)`：把顶层对象收敛为 `{ sentiments, candidates, reviews, tradeSnapshots }`，任意非法输入降级为 `[]`。
- `normalizeReview(item, index)`：补齐复盘记录的默认值（如 `marketPhase: '未标注'`、`errorType: '无'`、`disciplined` 三态）。
- `normalizeTradeSnapshot(item, index)`：交易快照结构 + `compactTradeData` 裁剪分时点（最多 500）。
- `normalizeMarketSnapshot(value)`：兼容扁平对象与 `{ market: {...} }`、英文/中文键别名，产出标准字段。

### 统计与过滤
- `analyzeSentiment(record)`：由涨跌停数算出 `breadth`、`breadthLabel`、阶段动作 `action`。
- `scoreCandidate(checks)`：五维（market/theme/trend/volume/risk）计数与标签。
- `summarizeReviews(reviews)`：总数、纪律执行数/率、纠错次数、高频错误。
- `filterReviews(reviews, filters)`：按日期区间、环境、周期位置、阶段、错误类型、纪律、关键词过滤并排序。

### 幂等合并
- `mergeTradeResultWithSnapshot(result, previous)`：同日分区不可用时沿用上一条成功快照，输出 `preservedSections`。
- `upsertTradeSnapshot(value, result, now)`：按 `tradeDate` 幂等 upsert，受 `TRADE_SNAPSHOT_LIMIT` 限制，按 `dataFingerprint` 判重。
- `upsertAutoReview(reviews, record, now)`：按稳定 `id` 幂等更新，保留 `createdAt`，更新 `updatedAt`；`dataFingerprint`+`manualFingerprint` 均未变更则原样返回。

## 3.4 `src/research-components.js` — 研究/复盘组件层

| 项 | 内容 |
| --- | --- |
| 职责 | 「情绪分析 / 选股研究 / 股市复盘 / 今日交易数据」的 React 界面 |
| 导出 | `SentimentApp`、`ScreenerApp`、`ReviewApp` |
| 依赖 | `react`、`./research.js` |
| 行数 | 约 500 行 |

### 内部工具与常量
`today()`（本地日期）、`Field`、`Empty`、`ReportDashboard`（知识规则复盘台）、`displayNumber`、`toneClass`。
常量：`CHECKS`（选股五维）、`emptyReviewForm()`、`emptyReviewFilters()`、`REVIEW_SOURCES`、`SAFETY_CHECKS`（6 项门禁）、`REVIEW_STEPS`（4 步）。

### `SentimentApp({ data, onChange })`
今日情绪记录表单（日期/阶段/涨跌停/最高板/备注）→ 写入 `data.sentiments`（最多 50）；展示 `analyzeSentiment` 结果与最近记录列表，支持删除。

### `ScreenerApp({ data, onChange })`
候选股表单（代码/名称/题材）+ 五维研究清单勾选 → `scoreCandidate` 评分；写入 `data.candidates`，展示候选研究池与删除。

### `TradeDataDashboard({ state, date, snapshots, onDate, onRefresh, onUse })`（内部）
「今日交易数据」看板：日期选择 + 「已保存 N 天」下拉 + 「刷新并保存」+「生成复盘草稿」；四大指数条、`IntradayLine` 分时图、成交额卡、九档涨跌分布、涨停梯队、热门题材、昨日涨停表现、数据源降级状态。

- `IntradayLine({ trend })`：用 SVG `path` 画上证涨跌幅分时（内联计算缩放）。
- `storedTradeResult(record)`：把本地快照还原成接口同构结果，供离线/历史日期展示。

### `ReviewApp({ data, onChange })`（导出，最复杂）
三页签：`data`（今日交易数据）/ `write`（今日复盘）/ `history`（历史记录）。

核心函数：
| 函数 | 职责 |
| --- | --- |
| `requestReview(dateValue, force)` | 调 `/api/stock-quiz.recap`（`cache:'no-store'`、同源凭证） |
| `applyReviewResult(result)` | 把 `snapshot/report` 映射进可编辑 `form`（不落库） |
| `loadTradeData(force, dateValue)` | 采集 → 合并快照 → 幂等写入 → 更新 `tradeState` |
| `selectTradeDate(value)` | 选历史日期时优先读本地快照，否则请求 |
| `startAutoReview()` | 「开始今日复盘」→ 生成草稿 |
| `save(event)` | 必填校验 + `upsertAutoReview` 写入历史 |
| `remove(id)` | 二次确认后删除记录 |
| `applySnapshot()` | 解析 JSON 快照并填充表单 |
| `useEffect` | 首次加载 + 每 `120000ms` 自动刷新（`visibilityState` 可见时） |

`emptyReviewForm` 覆盖四轴（`marketRegime`/`cycleDirection`/`cyclePosition`/`turningSignal`/`expectation`/`reality`/`moneyEffect`）、广度指标、主线五步、持仓体检、纠错字段与 `safetyChecks`。

## 3.6 `src/questions.js` — 题库组装

| 项 | 内容 |
| --- | --- |
| 职责 | 定义基础题、把题目与知识点关联、导出题库与知识卡片 |
| 导出 | `QUESTION_BANK`、`KNOWLEDGE_CATALOG`、`CHAPTERS`、`KNOWLEDGE_CARDS`、`ALL_KNOWLEDGE_CARDS` |

- `BASE_QUESTIONS`：27 道手写题（源自《周期论交易员手册》与《野人哥交易实战笔记》）。
- `LEGACY_KNOWLEDGE_MAP`：把 27 道基础题的 `id` 映射到知识点 id。
- `QUESTION_BANK = BASE_QUESTIONS + EXTRA_QUESTIONS`，基础题补上 `knowledgeIds`。
- `KNOWLEDGE_CARDS`：13 条精简知识卡片（供 `Qa` 检索）。
- `ALL_KNOWLEDGE_CARDS`：由 `KNOWLEDGE_CATALOG` 映射而来（56 条）。

## 3.7 `src/catalog.js` — 知识点目录

| 项 | 内容 |
| --- | --- |
| 职责 | 56 个知识点的单一数据源 |
| 导出 | `KNOWLEDGE_CATALOG`、`CHAPTERS` |

- `KNOWLEDGE_CATALOG`：`c01–c23`（周期论交易员手册）+ `w01–w33`（野人哥交易实战笔记），每条含 `id/source/chapter/title/keywords/content`。
- `CHAPTERS`：由 catalog 去重派生，含 `key/source/chapter/count`。

## 3.8 `src/extra-questions.js` — 拓展题库

| 项 | 内容 |
| --- | --- |
| 职责 | 覆盖 `catalog.js` 中基础题未覆盖知识点的 36 道题 |
| 导出 | `EXTRA_QUESTIONS` |

每条已带 `knowledgeIds`，与 `catalog.js` 知识点一一对应；测试会校验 56 个知识点**全部被题库覆盖**。
