# 06 · 构建与运行

## 1. 环境要求

| 项 | 要求 |
| --- | --- |
| Node.js | `>=20`（`engines.node`） |
| 运行宿主 | 支持 DSH 插件体系的环境（提供 `@deepseek-ai/cordis` 与客户端 UI 包） |
| 包管理 | npm（`package.json` 中无 lock 约束，仓库以 `.tgz` 保存历史打包快照） |

本包**没有 `dependencies` / `devDependencies`**，无需 `npm install` 即可构建与测试（测试仅用 Node 内置模块）。

## 2. npm 脚本

来自 [package.json](file:///c:/Users/spring/Documents/stock_study/dsh-stock-quiz/package.json#L30-L35)：

```jsonc
{
  "scripts": {

    "test":   "npm run build && node test/quiz.test.mjs",
    "prepack": "npm run build"
  }

```

| 命令 | 作用 |
| --- | --- |
| `npm run build` | 生成 `lib/`：拷贝宿主模块 + 打包客户端 bundle |
| `npm run check` | 对 8 个源文件做语法检查（`node --check`，不执行） |
| `npm test` | 先 `build`，再跑 `test/quiz.test.mjs` 全量回归 |
| `npm run prepack` | `npm pack` / `npm publish` 前自动构建 |

## 3. 构建流程（`scripts/build.mjs`）

[build.mjs](file:///c:/Users/spring/Documents/stock_study/dsh-stock-quiz/scripts/build.mjs) 做两步：

### 步骤 1：拷贝宿主模块（原样复制 src → lib）

```js
await rm(lib, { recursive: true, force: true })
await mkdir(lib, { recursive: true })
for (const file of ['index.js', 'market-review.js', 'questions.js', 'catalog.js', 'extra-questions.js', 'research.js']) {
  await cp(resolve(src, file), resolve(lib, file))
}
```

拷贝的 6 个文件是**保持不变**的 ESM 模块，供宿主与测试直接 `import`。注意 `research-components.js` **不在**拷贝列表——它只被打包进客户端 bundle。

### 步骤 2：打包客户端 bundle → `lib/client.js`

```js
const bundleSource = (source) => source
  .replace(/^import .*\r?\n/gmu, '')      // 去掉 import 语句
  .replace(/^export const /gmu, 'const ') // 去 export
  .replace(/^export function /gmu, 'function ')
  .replace(/^export \{.*\}\r?\n?/gmu, '') // 去掉 export {}

// client.js 额外处理：react / react-dom 的 import 改写为 require
const client = (await readFile(resolve(src, 'client.js'), 'utf8'))
  .replace(/^import React, \{ useEffect, useState \} from 'react'\r?$/mu, "const React = require('react')\nconst { useEffect, useState } = React")
  .replace(/^import \{ createPortal \} from 'react-dom'\r?$/mu, "const { createPortal } = require('react-dom')")
  .replace(/^import .*\r?\n/gmu, '')
  .replace(/^export const inject /mu, 'const inject ')
  .replace(/^export function apply/mu, 'function apply')
```

拼接顺序（**顺序有意义**，后者可引用前者）：

```
catalog.js → extra-questions.js → questions.js → research.js → research-components.js → client.js
```

最终产物外层包裹：

```js
window.__ModuleLoader__.load({
  id: 'dsh-stock-quiz',
  factory: (require) => {
    const module = { exports: {} }
    /* 拼接的 6 个模块 */
    module.exports = { apply, inject }
    return module.exports
  },
})
```

要点：

- 由于模块间原本的 `import`/`export` 被剥离，所有顶层符号处于**同一作用域**；因此拼接顺序必须保证被引用符号先声明（例如 `research.js` 必须早于 `research-components.js`）。
- `id: 'dsh-stock-quiz'` 是客户端 bundle 的身份标识。
- 产物 `lib/client.js` 顶层必须以 `window.__ModuleLoader__.load({` 开头、且不含顶层 `import`（测试用 `assert.match` / `assert.doesNotMatch` 守住）。
- 构建脚本会先 `rm lib` 再重建，因此 `lib/` 是**纯产物目录，不应手工编辑**。

## 4. 测试（`test/quiz.test.mjs`）

单文件、`node:assert/strict`、退出码非 0 即失败。运行：

```bash
npm test
```

覆盖范围：

### （1）题库与知识点完整性
- `KNOWLEDGE_CATALOG.length >= 50`（实际 56）、`CHAPTERS.length >= 15`。
- 知识点 id 唯一、题目 id 唯一。
- 每题 `type ∈ {single, multiple, boolean}`、选项 ≥ 2、答案索引合法、解析长度 ≥ 20、有 `knowledgeIds` 且均存在于 catalog。
- **56 个知识点被题库 100% 覆盖**。
- 题库同时含周期论与野人哥来源、含多选与判断题。
- `ALL_KNOWLEDGE_CARDS.length === KNOWLEDGE_CATALOG.length`。

### （2）`research.js` 纯函数（用例见测试文件）
情绪分析、选股评分、复盘统计、归一化、过滤排序、去重、200/90 上限、快照合并且跨日不沿用等。

### （3）`market-review.js`
- `parseTencentQuotes` 字段解析。
- `analyzeMarketReview` 各阶段判定：主升、高潮、退潮、数据不足（含 `confidence < 0.5`、`missingReasons` 含 `limitUp`）。
- `buildTradeData` 的梯队、封板率、晋级率、题材、昨日表现、成交额对比。
- `registerMarketReviewRoute`：路径 `/api/stock-quiz.recap`、方法 `['GET']`、返回注销函数。

### （4）客户端产物与设计约束（`lib/client.js`）
- 顶层形态正确、无顶层 `import`。
- 关键文案存在：`股票学习应用`、`情绪分析`、`选股研究`、`交易复盘`、`今日交易数据`、`生成复盘草稿`、`保存复盘并进入历史` 等。
- 关键 DOM 契约存在：`name: 'sidebar.panellist'`、`name: 'main', key: PANEL_ID`、`ctx.layout.selectPanel(null)`、`document.body.style.overflow = 'hidden'`、`.sq-app{position:fixed;z-index:...}`。
- 关键"禁止项"不存在：`sidebar.footer.action`、`sidebar.worktable`、`dsh-worktable`。
- 从 `src/research-components.js` 校验复盘页结构顺序（页签在 hero 之前）、无废弃的 `historyView` 等。

### （5）宿主与 manifest
- `lib/index.js` 含 `ctx.inject(['connection']` 与 `registerMarketReviewRoute`。
- `package.json` 的 `dsh.client.inject` 含两个官方包、**不含** `dsh-worktable`。

## 5. 本地运行 / 调试

本项目是 DSH 插件，**没有独立可执行的入口**，需在 DSH 宿主环境中加载：

1. 执行 `npm run build` 生成 `lib/`。
2. 在 DSH 宿主中安装/挂载本包（`cordis.patch.yml` 会把插件以 `id: stock-quiz` 插入 bundle）。
3. 宿主进程加载 `lib/index.js`（`main` / `exports["."]`）完成服务端路由注册。
4. 客户端加载 `lib/client.js`（`exports["./client"]`），经 `window.__ModuleLoader__` 注册槽位。
5. 打开 DSH Web，点击侧栏「股票学习」→ 全屏工作台出现；点击右上角「关闭」返回对话页。

不做完整宿主集成时，也可直接跑 `npm test` 验证逻辑与产物（测试会真实加载 `lib/*.js` 并对 `lib/client.js` 做文本契约校验）。

## 6. 打包与发布

```bash
npm pack          # 触发 prepack → build，产出 dsh-stock-quiz-<version>.tgz
```

- `package.json` 的 `files` 白名单只包含 `lib`、`cordis.patch.yml`、`README.md`，因此 `src/`、`test/`、`scripts/`、`template-*` 不会进入发布包。
- 仓库中保留了 `dsh-stock-quiz-0.1.0.tgz` ~ `dsh-stock-quiz-0.7.2.tgz` 的历史打包快照，可用于对比版本演进。
- `template-*.js` / `template-*.json` / `template-cordis.patch.yml` 是 DSH 插件脚手架参考样例（演示 `slots.register` 与 `__ModuleLoader__` 写法），**不参与构建**，也不在 `files` 白名单中。

## 7. 常见开发改动对应文件

| 想做的事 | 改动位置 | 记得 |
| --- | --- | --- |
| 加题 / 改题 | `src/extra-questions.js` 或 `questions.js` 的 `BASE_QUESTIONS` | 每题需带 `knowledgeIds`，且不能让覆盖率测试失败 |
| 加知识点 | `src/catalog.js` | 需同步补一道覆盖该点的题，否则测试 `Missing question coverage` 失败 |
| 改复盘规则/阈值 | `src/market-review.js` 的 `analyzeMarketReview` | 可能需同步更新 `ruleVersion` |
| 改界面 | `src/client.js`（测试/知识图谱/样式）或 `src/research-components.js`（情绪/选股/复盘） | 改完须 `npm run build` 才能进 `lib/` |
| 改持久化结构 | `src/research.js` 归一化函数 | 需考虑旧数据兼容与上限 |

> 注意：`lib/` 是构建产物，任何改动都应改 `src/` 后重新 `npm run build`；直接改 `lib/` 会在下次构建被覆盖。
