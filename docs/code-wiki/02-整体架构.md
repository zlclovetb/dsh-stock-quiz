# 02 · 整体架构

## 1. 双端（Host + Client）模型

`dsh-stock-quiz` 是一个 DSH 插件，同时向宿主（Node 进程）与浏览器（Web 客户端）提供代码。两条链路互相独立、通过一个同源 HTTP 接口通信：

```
┌──────────────────────────── 浏览器（DSH Web 客户端） ────────────────────────────┐
│                                                                                  │
│  lib/client.js  (window.__ModuleLoader__.load(...))                               │
│      ├── client.js              ── 全屏工作台 App / 知识测试 UI / STYLES           │
│      │      inject = ['slots', 'layout']                                          │
│      ├── research-components.js ── 情绪 / 选股 / 复盘 / 交易数据 组件               │
│      ├── research.js            ── 纯逻辑：归一化 / 统计 / 快照合并                 │
│      ├── questions.js           ── 题库 + 知识卡片                                 │
│      ├── catalog.js             ── 56 知识点目录                                   │
│      └── extra-questions.js     ── 36 拓展题                                       │
│                                                                                  │
│  注册扩展点：                                                                      │
│      ctx.slots.inject('main')              → 全屏 App（createPortal 到 body）       │
│      ctx.slots.inject('sidebar.panellist') → 侧栏「股票学习」入口图标               │
│      ctx.layout.selectPanel(null)          → 关闭工作台、返回对话页                 │
│                                                                                  │
└───────────────────────────────┬──────────────────────────────────────────────────┘
                                 │ fetch  GET /api/stock-quiz.recap?date=&force=
                                 │ (same-origin, credentials: same-origin)
┌───────────────────────────────▼──────────────────────────────────────────────────┐
│                              宿主（DSH / Node 进程）                                │
│                                                                                  │
│  lib/index.js   name = 'stock-quiz'                                               │
│      apply(ctx) → ctx.inject(['connection']) → host.effect(...)                   │
│      → registerMarketReviewRoute(connection)                                      │
│                                                                                  │
│  lib/market-review.js                                                             │
│      connection.fetch.register({ path: '/api/stock-quiz.recap', methods: ['GET'] })│
│      → buildMarketReview() → 采集 8 个数据分区 → analyzeMarketReview()            │
│                              └── 第三方公开行情：腾讯/东方财富/新浪                 │
└──────────────────────────────────────────────────────────────────────────────────┘
```

要点：

- **客户端 bundle 由构建脚本拼接而成**，而不是标准 ESM 逐文件加载。见 [06-构建与运行.md](./06-构建与运行.md)。
- **服务端仅注册一个 GET 路由**，职责是聚合公开行情并做规则分析，不持有任何用户数据；用户数据全部落在浏览器 `localStorage`。
- **两端不共享运行时状态**，唯一的契约是接口返回的 JSON 结构（`schemaVersion: 3`）。

## 2. DSH 集成机制

### 2.1 宿主侧注册（[src/index.js](file:///c:/Users/spring/Documents/stock_study/dsh-stock-quiz/src/index.js)）

```js
export const name = 'stock-quiz'

export function apply(ctx) {
  ctx.logger.info('[stock-quiz] 独立股票学习工作台已启用')
  ctx.inject(['connection'], (host) => {
    host.effect(
      () => registerMarketReviewRoute(host.connection),
      'stock-quiz: authenticated market review route'
    )
  })
}
```

- 通过 `ctx.inject(['connection'])` 等待 DSH 的 `connection` 服务就绪，再注册路由。
- `host.effect(fn, label)` 将路由的注册/注销绑定到插件生命周期，卸载时自动清理。

### 2.2 客户端侧注册（[src/client.js](file:///c:/Users/spring/Documents/stock_study/dsh-stock-quiz/src/client.js#L370-L374)）

```js
export const inject = ['slots', 'layout']

export function apply(ctx) {
  const FullscreenApp = () => React.createElement(App, { onClose: () => ctx.layout.selectPanel(null) })
  ctx.slots.inject('main', () => ctx.slots.register({ name: 'main', key: PANEL_ID }, FullscreenApp))
  ctx.slots.inject('sidebar.panellist', () => ctx.slots.register(
    { name: 'sidebar.panellist', id: PANEL_ID, order: 12, label: () => '股票学习' },
    PanelIcon
  ))
}
```

- `inject = ['slots', 'layout']` 声明依赖 DSH 的槽位服务与布局服务。
- `main` 槽位注册全屏 App（`key = PANEL_ID = 'stock-learning'`）；`sidebar.panellist` 槽位注册侧栏入口图标（`order: 12`，`label` 为「股票学习」）。
- 关闭动作通过 `ctx.layout.selectPanel(null)` 调用 DSH 官方布局 API，切回正常对话页面。

### 2.3 全屏覆盖的实现

`App` 组件返回 `createPortal(<div className="sq-app" role="dialog" aria-modal="true">…</div>, document.body)`：

- 用 `createPortal` 挂到 `document.body`，脱离宿主 DOM 层级，避免宿主侧栏压缩股票页面。
- 在 `useEffect` 中把 `document.body.style.overflow` 置为 `'hidden'`（卸载时还原）。
- `STYLES` 中 `.sq-app{position:fixed;z-index:2147483000;…}` 保证覆盖在 DSH 之上。
- 右上角「关闭」按钮 → `onClose` → `ctx.layout.selectPanel(null)`。

## 3. 客户端内部结构

### 3.1 装配层（`client.js`）

`App` 是唯一的状态容器，持有并分发以下状态：

| 状态 | 来源 | 持久化键 |
| --- | --- | --- |
| `progress` | `loadProgress()` | `dsh-stock-quiz.progress.v1` |
| `research` | `loadResearch()` → `normalizeResearchData()` | `dsh-stock-quiz.research.v1` |
| `navigation` | `localStorage` | `dsh-stock-quiz.navigation.v1` |
| `view` / `mode` / `paper` / `answers` / `result` / `qaInitial` | 组件内 `useState` | 内存（不持久化） |

`view` 路由（同一 `App` 内部切换，非路由库）：

```
quizHub ──► quiz ──► result ──► (qa)
   │          ▲
   ├──► coverage
   ├──► sentiment   → <SentimentApp data={research} onChange={updateResearch} />
   ├──► screener    → <ScreenerApp  data={research} onChange={updateResearch} />
   └──► review      → <ReviewApp    data={research} onChange={updateResearch} />
```

侧栏 `APP_ITEMS` 与视图对应：`quizHub`（知识测试，含 quiz/result/coverage/qa 子视图）、`sentiment`、`screener`、`review`。

### 3.2 逻辑层（`research.js`）

纯函数模块，**不依赖 React、不访问 DOM**，因此可被宿主测试直接 `import`（见 `test/quiz.test.mjs`）。职责分三类：

1. **归一化**：`normalizeResearchData` / `normalizeReview` / `normalizeTradeSnapshot` / `normalizeMarketSnapshot`（把任意输入收敛成稳定结构）。
2. **统计/评分**：`analyzeSentiment` / `scoreCandidate` / `summarizeReviews` / `filterReviews`。
3. **写回合并**：`upsertTradeSnapshot` / `mergeTradeResultWithSnapshot` / `upsertAutoReview`（幂等更新，避免重复与数据被 `null` 覆盖）。

### 3.3 组件层（`research-components.js`）

提供 `SentimentApp`、`ScreenerApp`、`ReviewApp` 三个导出组件（`TradeDataDashboard` 为 `ReviewApp` 内部子组件）。统一通过 `props.data`（来自 `App.research`）读取、`props.onChange(next)` 写回。

### 3.4 数据层（`questions.js` / `catalog.js` / `extra-questions.js`）

纯静态数据模块：

- `catalog.js` → `KNOWLEDGE_CATALOG`（56 条，id `c01–c23` 与 `w01–w33`）+ 派生 `CHAPTERS`。
- `extra-questions.js` → `EXTRA_QUESTIONS`（36 道，已带 `knowledgeIds`）。
- `questions.js` → `BASE_QUESTIONS`（27 道）+ `LEGACY_KNOWLEDGE_MAP`，组装为 `QUESTION_BANK`、`KNOWLEDGE_CARDS`、`ALL_KNOWLEDGE_CARDS`，并 re-export `KNOWLEDGE_CATALOG`、`CHAPTERS`。

## 4. 服务端数据流（复盘数据链路）

`buildMarketReview(options)` 是服务端核心流程（[src/market-review.js](file:///c:/Users/spring/Documents/stock_study/dsh-stock-quiz/src/market-review.js#L450-L487)）：

```
GET /api/stock-quiz.recap?date&force
        │
        ▼
buildMarketReview({ date, force })
        │
        ├─ 1. 指数分区 (indices)
        │      date 给定 → fetchHistoricalIndices(date)（东财日线，逐只 250ms 间隔）
        │      否则      → fetchIndices()（腾讯实时）
        │      失败即 throw（指数是硬依赖）
        │
        ├─ 2. 命中内存缓存？(CACHE_TTL_MS = 2min，key = 交易日)
        │      force !== true 且未过期 → 直接返回缓存（带 cached: true）
        │
        ├─ 3. 历史日期判定 isHistorical = 有 date 且 detectedDate ≠ 最新交易日
        │
        ├─ 4. 依次采集 8 个分区（每个分区前 sleep(1100ms) 限速）
        │      breadth      → fetchBreadth()       东财优先，失败降级新浪
        │      limitUp      → fetchPool(getTopicZTPool)
        │      broken       → fetchPool(getTopicZBPool)
        │      limitDown    → fetchPool(getTopicDTPool)
        │      yesterday    → fetchPool(getYesterdayZTPool)
        │      industries   → fetchIndustries()
        │      marketHistory→ fetchMarketHistory()
        │      trend        → fetchIndexTrend()
        │      历史日期下：breadth / industries / trend 标记为「仅提供最新交易日」并不可用
        │
        ├─ 5. partition(name, source, fn) 逐分区包裹 → 成功 ok / 失败 unavailable
        │      （单个分区失败不影响整体，第三方失败不会显示为真实 0）
        │
        ├─ 6. 分析：analyzeMarketReview(data)   → 四轴 + 赚钱效应 + 主线 + 风险灯 + 三套剧本
        │      建表：buildTradeData(data, {...}) → 交易数据看板结构
        │
        └─ 7. 汇总返回
               { ok, schemaVersion: 3, reportId: 'auto-recap:v1:<日期>:cn-a',
                 status: complete|partial, tradeDate, generatedAt, cached,
                 tradeData, snapshot, report, sources }
```

`status` 语义：

- `complete`：8 个分区全部 `ok`。
- `partial`：存在至少一个 `unavailable` 分区，报告会降级并在 `report.missingReasons` 中标注。

### 4.1 缓存与限速

- 模块级 `cache = new Map()`，键为交易日 `YYYYMMDD`，TTL 2 分钟；`force=1` 时绕过缓存并覆盖写入。
- 数据源请求统一走 `request()`，带 `timeout`（默认 12s）与 `retries`（默认 1，失败退避 `800ms * (attempt+1)`）以及 `AbortSignal.timeout`。
- 分区之间固定 `sleep(1100ms)`，避免触发第三方限流。

## 5. 客户端数据流（复盘页）

[ReviewApp](file:///c:/Users/spring/Documents/stock_study/dsh-stock-quiz/src/research-components.js#L212-L360) 是唯一需要访问服务端接口的组件：

```
挂载 useEffect
  ├─ loadTradeData(false, '')            首次自动采集当天
  └─ setInterval(120000)                  每 2 分钟自动刷新（页面可见时）

loadTradeData(force, dateValue)
  ├─ requestReview(date, force)   GET /api/stock-quiz.recap
  ├─ mergeTradeResultWithSnapshot(result, tradeResultRef.current)
  │     同日且某分区 unavailable → 沿用上一条成功快照，标记 preservedSections
  ├─ onChange(upsertTradeSnapshot(...))   幂等写入 data.tradeSnapshots（最多 90 天）
  └─ setTradeState({ loading, error, result })

startAutoReview()   「开始今日复盘」
  └─ applyReviewResult(result)   把 snapshot/report 映射进可编辑 form（不落库）

save(event)         「保存复盘并进入历史」
  ├─ 必填校验：date / mainline / symbol / plan / execution / lesson
  └─ onChange(upsertAutoReview(...))   稳定 id 幂等写入 data.reviews（最多 200 条）
```

两条关键约定（README 与测试都强调）：

1. **自动生成的复盘草稿只填充表单，不自动保存**；必须由用户确认/修改后点「保存复盘并进入历史」才写入 `reviews`。
2. **交易数据快照自动保存**（每天一份，刷新覆盖同日），与复盘历史是**相互独立**的两个流程。

## 6. 存储与持久化

| 键 | 结构 | 上限 | 归属 |
| --- | --- | --- | --- |
| `dsh-stock-quiz.progress.v1` | `{ attempts, wrongIds, masteredIds, testedKnowledgeIds, knowledgeStats }` | attempts 20 条 | 知识测试进度 |
| `dsh-stock-quiz.research.v1` | `{ sentiments, candidates, reviews, tradeSnapshots }` | reviews 200 / snapshots 90 / sentiments 50 | 研究数据 |
| `dsh-stock-quiz.navigation.v1` | `{ folded, rail }` | — | 应用栏折叠状态 |

损坏兜底：`loadResearch()` 解析失败时，把原始文本备份到 `dsh-stock-quiz.research.v1.corrupt.<时间戳>`，并返回 `canPersist: false` + 提示。

## 7. 设计约束（来自 README 与测试断言）

- 不依赖 `dsh-worktable`、不占用 `sidebar.footer.action`、不使用 `sidebar.worktable`（测试中有 `assert.doesNotMatch` 守住这些约束）。
- 不调用「量化复盘网」的私有加密接口，不绕过登录或订阅权限；严重异动预测与付费进阶指标不采集。
- 客户端 bundle 顶层必须是 `window.__ModuleLoader__.load({`，且不含顶层 `import`（测试断言）。
